# Course Assessment Framework and Marking Guide

**Course:** Computer Fundamentals and Artificial Intelligence Foundation Course  
**Academy:** Next Generation Academy  
**Duration:** 8 weeks | 40 lessons | 80 guided hours

## 1. Purpose of assessment

Assessment checks whether students can use computers safely, create useful digital work, explain important concepts and apply skills independently. It should support learning, not simply rank students.

Use:
- **Diagnostic assessment:** identify starting skills and support needs.
- **Formative assessment:** check learning during lessons through questions, observation and practice.
- **Weekly assessment:** review each week's practical and theory outcomes.
- **Summative assessment:** mid-course practical examination and final project.

## 2. Approved overall course assessment

| Component | Marks | Evidence |
|---|---:|---|
| Weekly practical activities | 30 | Weekly workbook tasks, saved outputs and instructor observations |
| Homework and assignments | 15 | Submitted tasks, quality, completion and improvement |
| Mid-course practical examination | 15 | Practical examination covering hardware, Windows, internet and Office |
| Final project and presentation | 30 | Website/project quality, understanding, repository, deployment and explanation |
| Theory, oral assessment and participation | 10 | Short quizzes, oral explanations, engagement and responsible practice |
| **Total** | **100** | |

**Recommended passing score:** 60/100, together with completion and presentation of the final project and demonstration of basic independent computer skills. The academy should publish its attendance, reassessment and certificate requirements separately.

Do not add all weekly 50-mark assessments to this 100-mark course score. Weekly scores are formative evidence used to inform the course-level categories above. The instructor should document how evidence contributes to each approved component.

## 3. Assessment principles

1. Share learning outcomes and assessment criteria before students start.
2. Assess the skill taught; do not surprise beginners with unpractised advanced tasks.
3. Accept correct explanations in a student's own simple words.
4. Award credit for safe method and understanding, not speed alone.
5. Keep individual results private.
6. Use fictional data for demonstrations and assessments.
7. Separate student quiz papers from instructor-only answer keys.
8. Give feedback that tells the student what was done well and what to practise next.
9. Provide a reasonable reassessment opportunity after support and reteaching.
10. Record evidence; do not mark a task complete only because it was demonstrated by the instructor.

## 4. Mid-course practical examination — 15 marks

| Task | Marks | Expected evidence |
|---|---:|---|
| Identify computer hardware | 3 | Correctly identifies selected components and explains a function |
| Windows and file management | 3 | Creates/organises a folder, saves and finds a file |
| Internet and email | 2 | Uses an approved browser and drafts a clear email safely |
| Word | 2 | Creates and formats a short document |
| Excel | 3 | Enters data and uses a basic formula correctly |
| PowerPoint | 2 | Creates a short, readable slide deck |
| **Total** | **15** | |

### Examination administration
- Prepare the same task instructions and time allowance for all students.
- Check that computers and required applications work before the examination.
- Use fictional names and data.
- Do not assess a student on an account or tool that they are not permitted to use.
- Record observed performance and any approved accommodation.
- If equipment fails, pause the affected student's time and provide an equivalent task or reschedule according to academy policy.

### Suggested practical observation scale
- **Full marks:** completes safely and independently; explains the result.
- **Partial marks:** completes most steps with a small prompt or checklist.
- **Limited marks:** completes some steps but needs repeated guidance.
- **No evidence yet:** cannot demonstrate the skill; provide reteaching and reassessment.

## 5. Final project and presentation — 30 marks

The approved Week 8 project is a personal portfolio or academy information website with Home, About, Services/Courses and Contact sections. Students should inspect and edit AI-generated code, create a GitHub repository and publish using an approved static hosting option where possible.

| Criterion | Marks | Evidence |
|---|---:|---|
| Website structure | 5 | Required sections, meaningful content and clear navigation |
| Design and responsive layout | 5 | Consistent layout, readable text and mobile-friendly presentation |
| Links and functionality | 4 | Navigation and links work; static contact form is not falsely presented as functional |
| Understanding and editing code | 5 | Student can explain HTML/CSS/JS roles and show meaningful edits |
| GitHub repository and README | 4 | Clear repository, organized files and useful README |
| Deployment | 3 | Live URL works, or deployment readiness is evidenced if access is unavailable |
| Presentation | 4 | Explains audience, design decisions, testing, AI assistance and learning |
| **Total** | **30** | |

### Final project integrity
- Students may use AI as a helper but must review and understand their code.
- Students must not publish passwords, tokens, private student data or unapproved photos.
- A static HTML contact form does not send messages unless a backend or approved form service is configured.
- Do not invent a live URL or claim a deployment succeeded if it did not.
- If internet or account access prevents deployment, assess the repository, local test and deployment worksheet honestly.

## 6. Theory, oral assessment and participation — 10 marks

Suggested evidence:
- Short oral explanations of key concepts.
- Correct use of vocabulary.
- Safe and respectful lab habits.
- Asking for help appropriately.
- Participation in practical work and peer collaboration.
- Honest disclosure of meaningful AI assistance.

Avoid awarding participation marks based only on confidence or speaking frequency. A quiet student can demonstrate excellent participation through practical work, careful questions and respectful teamwork.

## 7. Feedback and reassessment

Use this feedback format:

| Area | Instructor note |
|---|---|
| What the student did well | |
| Skill that needs improvement | |
| Practice task assigned | |
| Reassessment date | |
| Reassessment result | |

A student who does not yet meet a criterion should receive a specific practice activity and another opportunity to demonstrate the skill. Keep the original result and the reassessment result according to academy record policy.

## 8. Moderation and quality checks

Before an assessment:
- [ ] Questions match the taught learning outcomes.
- [ ] Instructions are clear and beginner-friendly.
- [ ] Time allowance is realistic.
- [ ] Required software and devices are available.
- [ ] Student and instructor versions are separate.
- [ ] Rubric marks add to the published total.

After an assessment:
- [ ] Marking is consistent across students.
- [ ] Unusual results or equipment issues are reviewed.
- [ ] Students receive useful feedback.
- [ ] Follow-up practice is recorded.
- [ ] Confidential results are stored securely.
