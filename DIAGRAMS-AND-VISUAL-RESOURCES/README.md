# Diagrams and Visual Resources

Visual learning aids are used throughout the weekly lesson files. The primary diagrams are embedded beside the topics they explain so students do not have to search in a separate folder.

## Where to find the visuals

- **Lessons 1–40:** conceptual Mermaid diagrams are embedded in the relevant lesson Markdown files. GitHub renders Mermaid diagrams directly in supported Markdown views.
- **Week 1:** [Computer Generations Timeline SVG](../WEEK-01-COMPUTER-FUNDAMENTALS/COMPUTER-GENERATIONS-TIMELINE.svg) — original educational vector timeline.
- **Week 1–8:** each weekly folder contains a visual or screenshot guide describing the genuine screenshots, equipment photos and classroom visuals that should be captured.

## Visual standards

- Place a diagram close to the lesson topic it explains.
- Use clear labels, readable text and simple visual flow.
- Add a short caption or surrounding explanation; students must be able to learn without relying only on an image.
- Use original assets or materials with suitable reuse permission.
- Record the source and licence/attribution for third-party assets.
- Remove names, email addresses, passwords, verification codes, serial numbers, licence keys, student data and private network details from screenshots.
- Capture real screenshots from academy-controlled devices; never fabricate software screenshots.
- Check that screenshots match the Windows, Office or application version used in class.
- Obtain required permission before photographing students or publishing their work.

## Academy capture plan

Before teaching, the instructor should capture and approve:
- Computer components and safe hardware handling.
- Genuine Windows desktop, File Explorer, Task Manager and Device Manager screens.
- View-only Disk Management example and instructor-controlled Windows Setup screens.
- Academy router, Ethernet and network status without exposing credentials.
- Word, Excel and PowerPoint examples using fictional data.
- AI tool examples using non-sensitive prompts and synthetic information.
- GitHub repository and deployment screenshots using a training project.

Store approved images in the relevant weekly folder or an assets subfolder and use relative paths. Do not add an image embed until the exact file has been uploaded and checked.
