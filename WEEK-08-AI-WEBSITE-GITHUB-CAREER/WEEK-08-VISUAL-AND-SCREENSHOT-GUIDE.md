# Week 8 — Visual and Screenshot Guide
## AI-assisted website development, GitHub and publishing

This guide identifies visuals to capture or create. It does not claim that live screenshots from academy software have already been captured.

## Screenshot capture plan
1. Capture VS Code with the project folder and starter files.
2. Capture a browser showing the local website.
3. Capture one HTML section and its matching CSS rule.
4. Capture a GitHub repository file list, README and commit history using a training/demo account.
5. Capture the current GitHub Pages settings and published page from the instructor demonstration repository.
6. Capture responsive tests at desktop and mobile widths.

## Privacy and security
- Use a dedicated demonstration account or sanitised screenshots.
- Hide email addresses, private repositories, account IDs, tokens, notifications and autofill.
- Never show passwords, recovery codes, API keys or student data.
- Do not show a student's public profile without consent.
- Do not publish academy logos, photographs or contact details without approval.

## Screenshot quality
Use readable resolution, crop unnecessary clutter, add concise captions and highlight one action at a time. Do not alter screenshots in a way that misrepresents a feature or successful deployment.

## Offline alternatives
Use printed screenshots, a prepared local website, a paper repository map or instructor demonstration. Students can complete project preparation and deployment worksheets when internet access is unavailable.

## Accessibility
Use meaningful captions and alt text, readable contrast, clear labels and keyboard-accessible demonstrations.
