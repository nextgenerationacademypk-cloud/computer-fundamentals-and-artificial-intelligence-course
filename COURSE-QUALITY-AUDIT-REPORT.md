## 3. Curriculum and learning progression

**Approved sequence preserved.**

The eight-week sequence is coherent for a beginner foundation course:

1. Computer concepts and hardware.
2. Windows and everyday computer operations.
3. System management, storage, installation concepts, internet and networking.
4. Word, Excel, PowerPoint and digital ethics.
5. AI foundations and prompt engineering.
6. AI-assisted research and office productivity.
7. AI-assisted graphic design, video and digital content.
8. AI-assisted website development, GitHub and career readiness.

The sequence builds from operating a computer to creating and publishing digital work. The course does not require prior programming knowledge. Tailwind CSS is not introduced here as a replacement for core CSS; the later Modern Web Development course remains the place for web-development depth.

### Strengths
- Simple-English, beginner-oriented teaching notes.
- Practical-first delivery model, approximately 20 minutes of theory and 90 minutes of practice, with review.
- Learning outcomes and evidence/checklists are included.
- Each lesson has an embedded visual workflow or concept diagram.
- Weekly workbooks, quizzes and instructor keys provide a consistent package.
- Projects connect weekly learning to visible outputs.
- Prompt Coach is integrated into the prompt-engineering lessons rather than added as an extra lesson.
- AI-assisted code generation is paired with code review, editing, testing and student explanation.

### Teaching-load consideration
The course is ambitious for 80 guided hours, particularly Weeks 6–8. Treat the listed AI tools as examples, not a requirement to master every product. Prioritize the learning outcome and one available tool; use prepared outputs or offline alternatives when access is limited. Do not sacrifice student practice to demonstrate many apps.

## 4. Technical and safety review

### Positive controls already present
- Hardware practice uses instructor supervision and a spare training desktop; the PSU must never be opened.
- Disk Management is view-only for students.
- Windows installation is restricted to a disposable virtual machine or dedicated spare training PC under direct supervision.
- Backups, correct target confirmation, licensing and recovery planning are required.
- Network activities are restricted to academy-approved networks.
- Phishing examples are fictional; student inboxes and passwords are not used for demonstrations.
- AI guidance warns against submitting passwords, verification codes, private student records and confidential academy data.
- Students are expected to verify AI facts, citations, formulas, documents, images and code.
- Website publishing guidance warns against exposing secrets and falsely describing a static contact form as functional.

### Current Windows support correction
The instructor manual and Week 2 README now state that the lab should use a currently supported Windows edition and prefer a supported Windows 11 release on compatible hardware. Windows 10 Home/Pro reached end of support on 14 October 2025. An applicable Extended Security Updates arrangement or separate edition lifecycle must be verified before any Windows 10 device is used. See [Microsoft's Windows 10 end-of-support guidance](https://support.microsoft.com/en-us/windows/deployment/updates-lifecycle/windows-10-support-has-ended-on-october-14-2025).

### Additional pre-delivery technical checks
- Confirm the exact Windows edition/build, device compatibility and update status.
- Confirm Microsoft Office licensing or prepare LibreOffice.
- Check whether NotebookLM, Gamma, Canva, video-generation tools and other AI services are available in the academy's region and on the devices used.
- Check current provider terms, minimum age, account requirements, free limits and privacy settings. Do not bypass age restrictions or require a paid subscription for a core outcome.
- Confirm GitHub account eligibility and publishing rules before the Week 8 project.
- Test every demonstration on the actual lab devices; menus and features may differ from screenshots or lesson descriptions.

## 5. Assessment and project alignment

The course-level 100-mark framework is documented separately:

| Component | Marks |
|---|---:|
| Weekly practical activities | 30 |
| Homework and assignments | 15 |
| Mid-course practical examination | 15 |
| Final project and presentation | 30 |
| Theory, oral assessment and participation | 10 |
| **Total** | **100** |

The recommended pass is 60/100, together with final project submission/presentation and basic independent computer skills. Weekly 50-mark assessments are formative evidence and must not be added together as a second course total.

The final website project rubric totals 30 marks and checks structure, responsive design, functionality, code understanding, GitHub/README, deployment and presentation. If account or internet restrictions prevent deployment, students can submit repository-ready work and deployment evidence; no fake live URL should be accepted.

### Remaining repository polish
1. The GitHub About description and topics should be set by the repository owner in GitHub's repository settings; the current connector workflow did not update repository metadata.
2. Choose and add an explicit content licence only if the academy intends to grant reuse rights. A public repository without a licence does not automatically grant permission to reuse its original course content.
3. Capture genuine academy screenshots and hardware photos, remove private details and embed approved images in the relevant lessons.
4. Review Mermaid diagrams on the actual student devices, including mobile screens; provide a simple image/PDF alternative if the diagram is difficult to read.
5. Keep completed assessment records and student feedback in a private academy location, never in the public repository.
