# Week 4 Visual and Screenshot Capture Guide

## Visual approach
Use conceptual diagrams and annotated examples near the relevant lesson topics. Genuine screenshots should be captured from the software version installed in the academy lab. Do not create fake screenshots or label a conceptual drawing as an actual application screen.

## Suggested embedded diagrams
- Lesson 16: document workflow — create → edit → format → review → save/export.
- Lesson 17: document structure — title → heading levels → body sections → contents.
- Lesson 18: workbook → worksheet → rows/columns → cell/range hierarchy.
- Lesson 19: data → formula/function → verified result → chart.
- Lesson 20: presentation planning → slide design → source check → delivery.

## Academy screenshot capture plan
| Lesson | Genuine screenshot/photo | What it should teach |
|---|---|---|
| 16 | Word window with Ribbon, document area and status bar | Identify interface areas |
| 17 | Heading styles, table insertion and page number | Build a structured report |
| 18 | Excel workbook with headers, rows, columns and selected cell | Understand spreadsheet structure |
| 19 | Formula bar showing SUM/IF and a simple chart | Connect formulas to results |
| 20 | PowerPoint slide layout, speaker notes and source slide | Create and present responsibly |

## Screenshot standards
1. Use the academy's installed version and note the application/version where useful.
2. Capture a clean sample file using fictional data.
3. Hide account names, email addresses, licence details and private files.
4. Crop to the feature being taught while retaining enough context.
5. Use readable resolution, descriptive alt text and a short caption.
6. Do not include student personal data or copyrighted third-party content without permission.
7. Keep image names consistent, for example W04-L18-excel-table-headers.png.
8. Record the creator and permission/licence for images added to the repository.

## Placement
Store images in this week folder or a dedicated assets/ subfolder. Embed beside the explanation with relative Markdown paths only after the exact image file exists.

## Instructor checklist
- [ ] Visual matches the application version used in class.
- [ ] Sample data is fictional.
- [ ] No private account or student details are visible.
- [ ] Caption and alt text explain the learning point.
- [ ] Permission/source is recorded.
- [ ] Image is readable on a phone and desktop.
